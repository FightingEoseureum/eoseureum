# 기술 스택 탐지 — 동작 방식 & 새 기술 추가 방법

## 자동 추가되는가?
**예.** 스캔할 때마다 자동으로 탐지·추가됩니다.
- 매 스캔의 응답(헤더/쿠키/본문/경로)을 `technology_fingerprint.py` 가 분석 →
  `analysis["technologies"]` 에 저장.
- `SERVICE_SCAN_USE_NMAP=true` 면 nmap -sV 가 식별한 서비스/버전도 추가.
- "기술 스택" 페이지(`/api/techstack`)는 이 결과를 호스트별로 집계해 자동 표시.
- 즉, **사용자가 수동 입력할 필요 없음.** 단, "탐지할 수 있는 기술의 종류"는
  fingerprint 규칙에 정의된 것만 인식한다(아래로 확장 가능).

## 현재 탐지 가능한 기술 (코드 규칙)
서버: Apache HTTPD / Apache Tomcat / Nginx / IIS / PHP / Node·Express /
      Spring Boot / WordPress / phpMyAdmin / Jenkins / Grafana / Kibana
프론트엔드: React / Vue.js / Angular / Next.js / Nuxt / Svelte / jQuery
+ nmap -sV 가 식별하는 임의 서비스/버전(고정 목록 아님)

## 새 기술 추가 방법 (코드 규칙 추가)
`backend/technology_fingerprint.py` 의 `fingerprint()` 함수 안, 기존 `_add(...)`
블록들 사이(프론트엔드 블록 위/아래 등)에 한 블록을 추가하면 됩니다.

사용 가능한 신호 변수:
- `server_l`   : Server 헤더(소문자)
- `xpb_l`      : X-Powered-By 헤더(소문자)
- `headers`    : 응답 헤더 dict(키 소문자)
- `cookies_l`  : 쿠키 이름 목록(소문자)
- `html_l`     : 응답 본문(소문자)
- `has_path_active("/경로")` : 해당 경로가 404/410 이 아닌지(존재/접근제어)
- `path_status("/경로")`     : 경로의 HTTP 상태코드

`_add(tech, "기술명", 가중치, "탐지 근거(증거)", [추천 점검 경로])`
- 가중치: `_W_STRONG`(70, 전용 헤더/쿠키 등 확정) / `_W_MEDIUM`(40, 강한 정황) /
          `_W_WEAK`(20, 보조 정황). 같은 기술에 여러 번 호출하면 점수가 누적됨.
- 점수 → 신뢰도(0~100): 70+ = 높음 / 40~69 = 보통 / <40 = 낮음.

### 예시 1) Express 보다 구체적인 "Django" 추가
```python
    # ---- Django ----
    django_probes = ["/admin/", "/static/admin/"]
    if "csrftoken" in cookies_l or "sessionid" in cookies_l:
        _add(tech, "Django", _W_MEDIUM, "Django 쿠키(csrftoken/sessionid) 관측", django_probes)
    if "wsgiserver" in server_l or "gunicorn" in server_l:
        _add(tech, "Django", _W_WEAK, "WSGI/gunicorn 서버 헤더", django_probes)
    if has_path_active("/admin/") and "django" in html_l:
        _add(tech, "Django", _W_STRONG, "/admin/ Django 관리 페이지 + 본문 표기", django_probes)
```

### 예시 2) 프론트 프레임워크 "Svelte Kit" 추가
```python
    if "__sveltekit" in html_l or "/_app/immutable/" in html_l:
        _add(tech, "SvelteKit", _W_STRONG, "SvelteKit 마커(/_app/immutable/) 감지", [])
```

## 추가 후 확인
1. 테스트 추가 권장: `backend/tests/test_technology_fingerprint.py` 의
   `_names(html)` 헬퍼로 케이스 작성 → `pytest tests/test_technology_fingerprint.py`.
2. 서버 재시작 후 새 스캔부터 반영(기존 스캔 결과에는 소급 적용되지 않음).

## (선택) 코드 수정 없이 추가하고 싶다면
헤더/쿠키/본문 문자열 매칭만으로 충분한 단순 기술은, 향후
`custom_fingerprints.json`(데이터 기반 규칙 로더)을 도입하면 JSON 편집만으로
추가할 수 있습니다. 필요하면 요청 주세요 — 로더를 붙여드립니다.
