===================================================
  Eoseureum — 진행 현황 요약
  기준일: 2026-06-02
===================================================

■ 프로젝트 개요
  - FastAPI(백엔드) + React(프론트엔드) 구성의 보안 취약점 스캐너
  - KISA 주요정보통신기반시설 기술적 취약점 분석·평가 기준 적용
  - 백엔드 실행: backend/venv/Scripts/python.exe -m uvicorn main:app --host 0.0.0.0 --port 8000
  - WebSocket 실시간 스캔 진행 (/ws/scan)

---------------------------------------------------
■ 스캔 파이프라인 (5단계)
---------------------------------------------------
  1. recon            정보수집 & 포트스캔       (scanner.py)
  2. active_probing   능동 취약점 점검          (active_probing.py)
  3. external_scan    외부 도구 심층 점검       (external_tools.py) ← 이번 세션 신규
  4. penetration      증거 수집 (스크린샷)      (screenshots.py)
  5. lateral_movement KISA 기준 분석 & 보고    (rule_engine.py)

---------------------------------------------------
■ 이번 세션에서 완료한 작업
---------------------------------------------------

[1] external_tools.py — 신규 생성
    외부 오픈소스 도구 5종 통합
    · testssl.sh  : SSL/TLS 취약점 점검 (JSON 파싱, "not vulnerable" 결과 제외)
    · nuclei      : CVE/설정 오류 템플릿 점검 (-no-interactsh, JSONL 파싱)
    · katana      : 웹 크롤링 (파라미터 포함 URL 수집 → ghauri 대상으로 전달)
    · ffuf         : 디렉터리 퍼징 (-fc 404,403, 민감 경로만 보고)
    · ghauri      : SQL 인젝션 자동화 (--dbs --batch, DB 목록 추출을 증거로 사용)
    · 미설치 도구는 자동 스킵 (graceful skip)
    · 모든 결과가 rule_engine 포맷(finding dict)으로 변환되어 analysis["findings"]에 병합

[2] wordlists/common.txt — 신규 생성
    ffuf용 약 160개 경로 wordlist
    (.env, .git, admin, actuator, api-docs, backup, phpmyadmin 등)

[3] main.py — 수정
    · from external_tools import run_all_external_tools 추가
    · active_probing 이후 external_scan 단계 삽입
    · external_findings를 analyze_with_rules() 결과에 extend

[4] ScanProgress.jsx — 수정
    · Terminal 아이콘 import 추가
    · STAGES 배열에 external_scan("외부 도구 심층 점검") 단계 추가

[5] rule_engine.py — 오탐 3건 수정
    · sensitive_path : 403 → 취약점 아님. config 파일은 실제 내용(_CONFIG_CONTENT_RE) 확인 후 보고
    · http_plaintext : 로그인 폼 또는 쿠키가 있을 때만 보고 (test 텍스트만 있는 페이지 제외)
    · sql_injection  : detection_steps에 curl 재현 명령어 + 응답 내 어디에서 데이터 출력되는지 명시

[6] scanner.py — 수정
    · has_login_form 감지 추가 (password 타입 input 또는 login/auth action form)

[7] active_probing.py — SQLi 오탐 수정 (이번 세션 마지막 작업)
    문제: curl 실행 시 302 리다이렉트(ModSecurity WAF 차단) 응답을 DB버전 노출로 오탐
    수정 내용:
    · _SQLI_VERSION_RE 강화: x.y.z 세 자리 이상 or DB명 명시 필요 ("HTML 2.0" 오탐 방지)
    · _WAF_BLOCK_RE 추가: modsecurity/blocked/errdoc.* 등 차단 페이지 감지
    · _probe_sqli_error   : status != 200 이면 즉시 건너뜀
    · _probe_sqli_union   : status != 200 제외 + WAF 페이지 제외 + 베이스라인 비교(원래부터 있던 문자열 제외)
    · _probe_sqli_bool    : status != 200 제외 + WAF 페이지 제외
    · _probe_sqli_time    : 베이스라인 응답시간 측정 후 "+3초 이상 유도된 지연"만 인정

[8] active_probing.py — 이전 세션에서 수정
    · _probe_ssrf 병렬 실행에서 제거 (body 텍스트 매칭 기반 오탐률 너무 높음)

[9] rule_engine.py — 이전 세션에서 수정
    · missing_header 체크 타입(CSP/X-Frame-Options/HSTS) 비활성화
      이유: 헤더 부재는 스크린샷·데이터로 실제 exploit 증명 불가

---------------------------------------------------
■ 설계 원칙 (유지할 것)
---------------------------------------------------
  - "스크린샷 또는 데이터로 증명할 수 없는 취약점은 보고하지 않는다"
  - XSS: Playwright alert() 실제 발생 확인 필수
  - SQLi: DB 에러 텍스트 or UNION 버전 추출 or 시간 지연(베이스라인 대비 +3초) 중 하나 실증
  - 민감경로: 200 + 실제 민감 내용 포함 확인 (403 → 차단됨 → 취약점 아님)
  - HTTP 평문: 로그인 폼 or 쿠키 있을 때만 보고

---------------------------------------------------
■ 현재 미완성 / 다음에 확인할 것
---------------------------------------------------
  - 외부 도구(testssl.sh, nuclei, ffuf, katana, ghauri)가 실제 실행 환경에 설치되어 있는지 확인 필요
    → 미설치 시 external_scan 단계는 "0건 발견"으로 자동 스킵됨
  - ghauri의 Windows 실행 경로가 올바른지 확인 (external_tools.py의 _ghauri_cmd() 참조)
  - 프론트엔드 빌드(npm run build) 여부 — 현재 개발 서버 또는 dist 폴더 확인 필요
